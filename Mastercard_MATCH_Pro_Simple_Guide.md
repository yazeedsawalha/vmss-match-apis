# Mastercard MATCH Pro — Simple Integration Guide

## 1. Service overview

**Service name:** Mastercard MATCH Pro.  
**Purpose:** Check whether a prospective merchant or its owners may match previously terminated merchant records before enabling card acceptance.

**Why use it?** It gives the bank information about prior merchant terminations to support onboarding and risk review. A possible match needs investigation; it does not automatically mean reject the merchant.

## 2. Authentication

**Method:** OAuth 1.0a with RSA-SHA256 request signing.

### What you need

| Item | Mandatory? | Description |
| --- | --- | --- |
| Consumer key | Yes | Identifies your Mastercard application. |
| Signing key (`.p12`) | Yes | Private key used to sign each request. |
| Key alias | Yes | Selects the signing key inside the keystore. |
| Keystore password | Yes | Unlocks the signing key. |
| Acquirer ICA | Yes | Your institution's authorized identifier; sent as `acquirerId`. Sandbox uses `1996`. |

### Steps

1. Create a Mastercard Developers project and select **MATCH Pro**.
2. Download the sandbox credentials and signing key.
3. Load the key using its alias and password.
4. Build the final URL and JSON body, then use Mastercard's OAuth signing library to generate the `Authorization` header.
5. Send the request with the exact URL and JSON body that were signed. Generate a fresh signature for each call.

Keep the key and password on the backend. Production requires separate approved access and credentials.

### Authorization header contents

The signing library creates these values inside **one** `Authorization` header.

| OAuth parameter | Mandatory for this POST? | Description |
| --- | --- | --- |
| `oauth_consumer_key` | Yes | Your consumer key. |
| `oauth_nonce` | Yes | Unique random request value. |
| `oauth_timestamp` | Yes | Current Unix time in seconds. |
| `oauth_signature_method` | Yes | `RSA-SHA256`. |
| `oauth_version` | Yes | `1.0`. |
| `oauth_body_hash` | Yes | Hash of the JSON body. |
| `oauth_signature` | Yes | Generated request signature. |

## 3. API — Screen a merchant

**Method:** `POST`  
**Path:** `/termination-inquiries`

| Environment | Base URL |
| --- | --- |
| Sandbox | `https://sandbox.apiedge.mastercard.com/mcp/match/api` |
| MTF / UAT | `https://apiedge.mastercard.com/mtf/mcp/match/api` |
| Production | `https://apiedge.mastercard.com/mcp/match/api` |

### Request headers

| Header | Mandatory? | Description / value |
| --- | --- | --- |
| `Authorization` | Yes | OAuth value generated by the signing library. |
| `Content-Type` | Yes | `application/json`. |
| `Accept` | No; recommended | `application/json`. |

```http
POST https://sandbox.apiedge.mastercard.com/mcp/match/api/termination-inquiries
Content-Type: application/json
Accept: application/json
Authorization: OAuth oauth_consumer_key="<KEY>",oauth_nonce="<NONCE>",oauth_timestamp="<SECONDS>",oauth_signature_method="RSA-SHA256",oauth_version="1.0",oauth_body_hash="<HASH>",oauth_signature="<SIGNATURE>"
```

### Optional query parameters

| Parameter | Type | Mandatory? | Description |
| --- | --- | --- | --- |
| `page_offset` | integer | No | Pagination offset; default `0`. |
| `page_length` | integer | No | Results per page, 1–100; default `100`. |
| `internal_inquiry` | boolean | No | Internal inquiry flag; default `false`. |
| `show_perf_indicators` | boolean | No | Request additional indicators where available and entitled; default `false`. |

## 4. Request fields

Required children apply when their parent object is included. Field names are case-sensitive.

### Request wrapper

| Field path | Type | Mandatory? | Description |
| --- | --- | --- | --- |
| `terminationInquiryRequest` | object | Yes | Request wrapper; exact casing is required. |
| `terminationInquiryRequest.acquirerId` | string | Yes | ICA identifier, digits only, 1–11 characters. |
| `terminationInquiryRequest.merchant` | object | Yes | Merchant and principal-owner details. |

### Merchant

Inside `terminationInquiryRequest.merchant`:

| Field | Type | Mandatory? | Description / validation |
| --- | --- | --- | --- |
| `name` | string | Yes | Business name, 1–255 characters. |
| `doingBusinessAsName` | string | No | Trading name, up to 255 characters. |
| `merchantId` | string | No | Acquirer-assigned merchant identifier; up to 25 characters; letters, digits, hyphens. |
| `subMerchantId` | string | No | Submerchant identifier; same character rules; up to 25 characters. |
| `address` | object | Yes | Merchant location; see address table. |
| `phoneNumber` | string | Yes | Digits only, maximum 25; no country code. US numbers must have 10 digits and cannot start with 0 or 1. |
| `altPhoneNumber` | string | No | Alternate phone; same phone formatting rules. |
| `merchantCategory` | string | Yes | Applicable numeric MCC; schema maximum length 4. Preserve leading zeros. |
| `nationalTaxId` | string | Conditional | Mandatory for Brazil; otherwise optional; maximum 35 characters. |
| `countrySubdivisionTaxId` | string | No | Regional tax identifier; maximum 35 characters. |
| `urls` | array of strings | No | Business websites. Combined URLs: maximum 20,000 bytes. |
| `principals` | array of objects | Yes | Principal owners. Provide the business owners, up to five. |
| `searchCriteria` | object | No | Matching configuration. |
| `searchCriteria.minPossibleMatchCount` | string | No | Minimum phonetic-match count; value `"1"`–`"9"`. Example `"3"`. |

### Address

Used by both `merchant.address` and `merchant.principals[].address`:

| Field | Type | Mandatory? | Description / validation |
| --- | --- | --- | --- |
| `addressLineOne` | string | Yes | Street address; 1–100 characters. |
| `addressLineTwo` | string | No | Additional address information; up to 100 characters. |
| `city` | string | Yes | City; 1–30 characters. |
| `isOtherCity` | string | Conditional; follow city rule | `N` if the city exists in the Cities API; `Y` if absent. Supply the city text in either case. |
| `countrySubdivision` | string | Conditional | Required for US/Canadian locations; use the supported subdivision code. Schema maximum 3 characters. |
| `country` | string | Yes | ISO 3166-1 alpha-3 code; exactly 3 characters, e.g. `JOR`, `USA`, `CAN`. |
| `postalCode` | string | Conditional | Required for US/Canada; optional elsewhere. US: exactly 5 digits. Other countries: maximum 10 characters using letters, digits, spaces or hyphens. |

Set `isOtherCity` using the Cities API: `N` if listed, otherwise `Y`. Use `GET /countries/{country_code}/cities` for the lookup.

### Principal owners

Inside `merchant.principals[]`:

| Field | Type | Mandatory? | Description / validation |
| --- | --- | --- | --- |
| `firstName` | string | Yes | Owner first name; 1–255 characters. |
| `middleInitial` | string | No | One alphanumeric character. |
| `lastName` | string | Yes | Owner last name; 1–255 characters. |
| `address` | object | Yes | Owner address; see address table. |
| `phoneNumber` | string | Yes | Same phone rules as merchant. |
| `altPhoneNumber` | string | No | Alternate phone, same rules. |
| `email` | string | Yes | Owner email; maximum 100 characters. |
| `driversLicense` | object | No | License information; conditional children below. |
| `dateOfBirth` | string | No | Owner birth date in `yyyy-MM-dd` format. |
| `nationalId` | string | Conditional | Required for Brazil; maximum 35 characters. Leave blank where the documented business rule says not applicable. |

### Optional driver’s license details

| Field | Type | Mandatory? | Description / validation |
| --- | --- | --- | --- |
| `driversLicense.number` | string | No | License identifier; maximum 35 characters. Supply with its issuing-country information. |
| `driversLicense.country` | string | Conditional | Required when license number is supplied; three-letter country code. Do not send without a license number. |
| `driversLicense.countrySubdivision` | string | No; US/Canada only | US/Canada only; standard two-letter subdivision code. Omit for other countries. |

Use Latin-script names and addresses that satisfy Mastercard’s field patterns. Keep phone numbers and identifiers as strings.

## 5. Response

A successful call returns HTTP `200`. Save the **Inquiry Reference Number (IRN)** and review any possible matches.

### Main response fields

The response table describes the fields to consume. “No” means not guaranteed by the published envelope schema; fields marked “Yes” are required within their returned object. Handle missing expected success data as an error, not a clean screening result.

| Field | Type | Mandatory in schema? | Description |
| --- | --- | --- | --- |
| `terminationInquiryResponse` | object | No; expected on success | Response wrapper. |
| `terminationInquiryResponse.pageOffset` | integer | No | Returned page offset. |
| `terminationInquiryResponse.ref` | string | No; expected on success | IRN; store for future reference. |
| `terminationInquiryResponse.possibleMerchantMatches` | array | No | Match result containers. |
| `possibleMerchantMatches[].totalMerchantMatches` | integer | No | Total possible match count. |
| `possibleMerchantMatches[].terminatedMerchants` | array | No | Reported merchant records. |
| `terminatedMerchants[].merchant` | object | No | Business and termination details. |
| `terminatedMerchants[].merchantMatch` | object | No | Field-level matching codes. |
| `terminationInquiryResponse.merchantPerformanceIndicator` | object | Conditional | Additional indicators when requested, available, and entitled. |

Shorter paths above continue beneath `terminationInquiryResponse.possibleMerchantMatches[]`.

### Merchant fields used in the example

Inside `terminatedMerchants[].merchant`:

| Field | Type | Mandatory in returned object? | Description |
| --- | --- | --- | --- |
| `name` | string | Yes | Reported business name. |
| `merchantId` | string | Yes | Merchant identifier. |
| `phoneNumber` | string | Yes | Business phone. |
| `merchantCategory` | string | Yes | MCC. |
| `dateOpened` | string | Yes | Agreement start date. |
| `dateClosed` | string | Yes | Termination date. |
| `createdDate` | string | Yes | Date the record was added. |
| `addedByAcquirerId` | string | Yes | Reporting acquirer's ICA. |
| `reasonCode` | string | Yes | Termination reason code. |
| `reasonCodeDesc` | string | Yes | Termination reason text. |
| `merchRefNum` | string | Yes | Merchant record reference; different from the IRN. |

Inside `merchantMatch`, `name`, `address`, and `phoneNumber` are optional string match codes. Interpret them using Mastercard's official code definitions.

## 6. How to use the result

1. Save `terminationInquiryResponse.ref` against your onboarding application.
2. Review returned merchant matches and termination reasons using the bank's risk process.
3. If the completed inquiry has no matches, continue the remaining onboarding checks.
4. If the request fails or the result is incomplete, keep screening pending/error.

| HTTP status | Description | Action |
| --- | --- | --- |
| `200` | Inquiry completed | Process the response. |
| `400` | Invalid request | Correct the request data. |
| `401` | Authentication failure | Check credentials and signing. |
| `403` | Access denied | Check institution entitlement. |
