# Mastercard MATCH Pro

## Screen a merchant

Checks whether a merchant or its owners may match previously terminated merchant records. Use this during onboarding to identify possible risk before enabling card acceptance.

> **Result:** Possible match → risk review. No match → continue onboarding. Failed or incomplete check → keep screening unresolved.

### Endpoint

| Method | Path | Request / response format |
| --- | --- | --- |
| **POST** | `/termination-inquiries` | `application/json` |

| Environment | Base URL |
| --- | --- |
| Sandbox | `https://sandbox.apiedge.mastercard.com/mcp/match/api` |
| MTF / UAT | `https://apiedge.mastercard.com/mtf/mcp/match/api` |
| Production | `https://apiedge.mastercard.com/mcp/match/api` |

## Authentication

**OAuth 1.0a · RSA-SHA256**

| Required credential | Description |
| --- | --- |
| Consumer key | Identifies your Mastercard application. |
| Signing key (`.p12`) | Private key used to sign each request. |
| Key alias and password | Load the signing key from the keystore. |
| Acquirer ICA | Your authorized institution identifier; sent in the body as `acquirerId`. |

1. Create a Mastercard Developers project with **MATCH Pro** and obtain the credentials.
2. Load the signing key using the alias and password.
3. Use the [official OAuth library](https://github.com/Mastercard/oauth1-signer-java) to sign the HTTP method, final URL, and final JSON body. It generates the body hash and OAuth header.
4. Send the generated header with the exact signed body. Generate a fresh signature for every call.

No token endpoint is needed. Use approved environment credentials; production access requires Mastercard approval.

## Request

### Headers

| Header | Type | Required | Description / value |
| --- | --- | --- | --- |
| `Authorization` | string | Yes | Full `OAuth ...` value generated by the signing library. |
| `Content-Type` | string | Yes for JSON | `application/json`. |

### Body schema

Include only the fields below and any applicable regional fields. Names are case-sensitive. All paths are relative to `terminationInquiryRequest` unless shown as the wrapper itself.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `terminationInquiryRequest` | object | Yes | Top-level request wrapper. |
| `acquirerId` | string | Yes | Authorized ICA; 1–11 digits. Sandbox uses `1996`. |
| `merchant` | object | Yes | Merchant and owner data. |
| `merchant.name` | string | Yes | Business name; 1–255 characters. |
| `merchant.phoneNumber` | string | Yes | Digits only, without country code; maximum 25 digits. |
| `merchant.merchantCategory` | string | Yes | Applicable MCC, e.g. `5732`; preserve leading zeros. |
| `merchant.address` | object | Yes | Business address. |
| `merchant.address.addressLineOne` | string | Yes | Street address; 1–100 characters. |
| `merchant.address.city` | string | Yes | City; 1–30 characters. |
| `merchant.address.country` | string | Yes | Three-letter country code, e.g. `JOR`. |
| `merchant.principals` | array of objects | Yes | Actual business owners; up to five. |
| `merchant.principals[].firstName` | string | Yes | Owner's first name; 1–255 characters. |
| `merchant.principals[].lastName` | string | Yes | Owner's last name; 1–255 characters. |
| `merchant.principals[].phoneNumber` | string | Yes | Digits only, without country code. |
| `merchant.principals[].email` | string | Yes | Owner email; maximum 100 characters. |
| `merchant.principals[].address` | object | Yes | Owner address. |
| `merchant.principals[].address.addressLineOne` | string | Yes | Street address; 1–100 characters. |
| `merchant.principals[].address.city` | string | Yes | City; 1–30 characters. |
| `merchant.principals[].address.country` | string | Yes | Three-letter country code. |

Use Latin-script names/addresses that satisfy the provider's patterns. Keep identifiers and phone numbers as strings.

### Conditional fields

| Field | Required when | Description |
| --- | --- | --- |
| Address `isOtherCity` | Follow the documented city lookup rule | `N` if the city is returned by the Cities API; otherwise `Y`. Optional in the schema. Applies to business and owner addresses. |
| Address `countrySubdivision` and `postalCode` | US/Canada address | State/province and postal code; applies to business and owner addresses. |
| `merchant.nationalTaxId` / `merchant.principals[].nationalId` | Brazil | Required regional identifiers. |

## Responses

### `200` — Inquiry completed

Read these fields to determine the business outcome. The table lists the fields **used by this integration**, not every field returned by Mastercard.

| Response field | Type | Used for | Description |
| --- | --- | --- | --- |
| `terminationInquiryResponse.ref` | string | Tracking | Inquiry Reference Number (IRN). Save with the onboarding application. |
| `terminationInquiryResponse.possibleMerchantMatches` | array | Decision | Match result groups. Inspect every group. |
| `possibleMerchantMatches[].totalMerchantMatches` | integer | Decision | Number of possible matches in the result group. |
| `possibleMerchantMatches[].terminatedMerchants` | array | Match evidence | Returned merchant records, when present. |

The last two paths continue beneath `terminationInquiryResponse`. The envelope schema does not guarantee all these fields; missing or unusable decision data must not be treated as zero matches.

**Response example — selected fields only:**

```json
{
  "terminationInquiryResponse": {
    "ref": "1996-250516085206-J9ZHK5KT",
    "possibleMerchantMatches": [
      { "totalMerchantMatches": 1 }
    ]
  }
}
```

### Match decision

| Condition | Return to your business flow |
| --- | --- |
| Any count is greater than `0`, or returned merchant records exist | `POSSIBLE_MATCH` |
| HTTP `200`, complete usable result, and explicitly zero matches | `NO_MATCH` |
| Failed call, missing/unusable result, inconsistent data, or incomplete pagination | `ERROR` |

**The example returns `POSSIBLE_MATCH`.** Do not default missing counts/arrays to zero. A possible match requires review; it is not an automatic rejection.

### Error responses

| HTTP status | Meaning | Action |
| --- | --- | --- |
| `400` | Invalid request | Correct the request data. |
| `401` | Authentication failure | Check credentials and request signing. |
| `403` | Insufficient permission | Check project access and authorized ICA. |
